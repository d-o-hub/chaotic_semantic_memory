# Plan: Fix v0.3.7 Failed GitHub Deployment

## Status Assessment

### v0.3.7 Deployment State (as of 2026-07-22)

| Registry | Expected | Actual | Status |
|----------|----------|--------|--------|
| GitHub Release | v0.3.7 | v0.3.7 (all 6 assets) | DONE |
| npm CLI (`@d-o-hub/csm`) | 0.3.7 | 0.3.7 | DONE |
| npm WASM (`@d-o-hub/chaotic_semantic_memory`) | 0.3.7 | **0.3.6** | BROKEN |
| crates.io (`chaotic_semantic_memory`) | 0.3.7 | **0.3.6** | BROKEN |

### Root Causes (fixed in working tree, not yet committed)

1. **WASM build used wrong package** — `--features wasm` on root crate; should be `-p csm-wasm`
2. **WASM artifact name wrong** — looked for `chaotic_semantic_memory.wasm`, actual binary is `csm_wasm.wasm`
3. **npm wasm-pack ran from root** — should build from `crates/csm-wasm`
4. **wasm-opt metadata in wrong Cargo.toml** — was in root, needed in `crates/csm-wasm/Cargo.toml`
5. **No recovery mechanism** — once a tag exists, the release workflow skips entirely; no way to re-run for missing artifacts

## Uncommitted Changes (4 files)

## Potential Risks

1. **crates.io credential** — The `environment: crates.io` secret may have expired. If publish fails, check GitHub environment secrets.
2. **npm OIDC** — npm trusted publishers must be configured for the new workflow path. If npm publish fails with OIDC errors, see `npm-trusted-publishers` skill.
3. **wasm-opt availability** — The recovery inject step adds wasm-opt metadata if absent; wasm-pack may need `wasm-opt` binary installed. The workflow already has `cargo install wasm-pack` but doesn't explicitly install `wasm-opt` — this worked in v0.3.6 so it should be fine.
4. **crates.io rate limiting** — Publishing 7 workspace crates + 1 main crate in sequence with 20s delays; should be fine.
