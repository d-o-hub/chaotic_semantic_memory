## #899 — closed, re-created

Substance verified rather than taken on trust (delegated investigation + direct checks):

- Both edited files are **live**: `src/retrieval/graph_rag.rs` is a second implementation, not a
  re-export shim (it has its own `find_anchors`/`traverse_from`/`ConceptBuilder`), reachable from
  `framework_graph_rag.rs` and `benches/benchmark.rs`; the crate copy is reachable from crate
  consumers. So editing both is required, not the #689 dead-copy trap.
- The clamp runs at function entry, before the loops and allocations it bounds
  (`anchor_top_k`/`max_hops`/`final_top_k` `.min(MAX_*)`, then `if hop >= max_hops`,
  `results.truncate(final_top_k)`). `final_top_k ≤ 100_000` still admits a 100k-element vector —
  large but bounded, which is the CWE-770 tradeoff the added doc comment states.
- `pub` on the constants is **required**, not gratuitous: the root copy consumes them
  (`src/retrieval/graph_rag.rs:82-84`). #865's private-constant form could not clamp that surface.
- The values match the merged precedent for this parameter class:
  `pub const MAX_TOP_K_LIMIT: usize = 100_000` in `csm-retrieval/src/bm25.rs` (#684) — same
  magnitude for `final_top_k`, `pub const`, `.min()` at the boundary. House pattern, not an invented
  number.
- Tests are new with the change and cover both surfaces: `graph_rag_bounds_large_config_parameters`
  (all three parameters at `usize::MAX`) and `graph_rag_zero_final_top_k_returns_empty`.
  Local: `cargo test -p csm-retrieval --lib graph_rag` → 2 passed;
  `cargo test --lib retrieval::graph_rag` → 2 passed.
- `main` carries **no** clamps in either file (no `MAX_GRAPH_RAG*`, no `.clamp(`), so #865 never
  landed and no verdict can be inherited from it.
- Head shape: two `google-labs-jules[bot]` commits plus a human `Merge branch 'main' into …`,
  1 behind `main` — Rule 10's case. Re-created as a fresh branch off `main` (the PR this record ships
  in), one commit, honest scope (`fix(retrieval)`: the diff is `csm-retrieval`, and #865's own title
  used `retrieval`, while `fix(singularity)` is merely defensible by precedent).

## #900 — closed as submitted, not as rejected

Credited first, because it is better than expected: `experimental-svsc-4d = []` **is** declared
(`crates/csm-chaos/Cargo.toml:19`), the bench carries
`required-features = ["experimental-svsc-4d"]` (`:63`), and `lib.rs:15` / `maps/mod.rs:9` gate the
module on it — exactly the shape #866's verdict asked a research-map PR to adopt. CI is green
(39 checks, no failing annotations), and being invisible to CI is not this PR's fault: `csm-chaos`
is outside `workspace_default_members`, so the lint/test jobs never select it (#866's finding,
filed as #905).

Three blockers, each verified:

1. **Paper fidelity is unverifiable and the body admits it.** Citation marked
   `[FALLBACK — outside this run window]`, design described as "bit shifts and additions mapped to
   fractional multipliers" — an approximation of the paper's varying-multiplier 4D system. #866 was
   merged only because a reviewer could match its equations line by line
   (`CoupledLorenzMap::derivatives` ≡ arXiv:2609.23276 §2 eq. (8), RK4 as the paper's own scheme).
2. **The latency table has no artifact.** `~68.2 ns → ~5.5 ns` beside `Recall/quality: Not measured`,
   no Criterion output for `chaotic_hashing_svsc_4d` anywhere in the repo. The ADR-0095 gate does not
   fire on a `feat:` title; the rubric does.
3. **557 lines of unrelated `Cargo.lock` churn** (`+576/−557`) — a full `cargo update`
   (`hyper-rustls 0.27.9 → 0.27.10`, …) with nothing to do with the map. Direction checked, not
   assumed: it does **not** revert today's security bumps (`rustls 0.23.46`, `quinn-proto 0.11.19`,
   `chacha20 0.10.2` are identical in both trees), but it makes the PR unreviewable.

## Corrections to the delegated reports (recorded because they matter)

The delegated #900 report listed the undeclared feature and a security-bump revert as blocking
findings. Both are wrong, and both were one command away from being checked:
`git show <branch>:crates/csm-chaos/Cargo.toml` shows the feature declared, and
`git show <branch>:Cargo.lock` shows the branch carrying the same fixed versions as `main`
(the churn is additive). The lesson — a delegated conclusion is a lead, not evidence; and
`git diff A...B` reports against the *merge base*, so it cannot answer "does B revert A's fix" — is
appended to `progress/LEARNINGS.md`. The same delegation also left an untracked `ROAST_P900.md` in
the repo root despite being told not to write; it was removed, and `git status --short` after every
delegation is now part of the routine.
