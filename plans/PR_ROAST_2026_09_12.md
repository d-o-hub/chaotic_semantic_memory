# PR Roast 2026-09-12 — #689 "Fixed the Dead Copy" + Main-CI Failure Sweep

## Headline finding

PR #689 (`perf(retrieval): fix 0-based index in partial selection`) is a
correct-by-inspection micro-optimization applied to the **one copy of
`merge_results` that nothing in the repo executes**. The repo still has two
compiled, near-identical copies of the hybrid merge logic; the 2026-09-07
re-export-shim dedup covered `bm25`/`rerank` but **missed `hybrid`**:

| Copy | State after #689 | Who executes it |
|------|------------------|-----------------|
| `src/retrieval/hybrid.rs` (root) | still `select_nth_unstable_by(top_k,` at :144, :248 | the only production caller: CLI `src/cli/commands/query.rs:108` |
| `crates/csm-retrieval/src/hybrid.rs` | patched to `top_k - 1` (:179, :283) by #689 | zero production callers (types only are re-exported) |

The only benchmark harness, `benches/hybrid_benchmark.rs:3-5`, imports the
**root** copy — so no bench in the repo can measure #689's edit, and no
production path runs it. The introducing PR #529 explicitly promised
"dual-surface parity for src and csm-retrieval"; #689 ends that parity at
exactly the two lines it claims to fix.

## Why it is not a correctness fix

`select_nth_unstable_by(top_k, cmp)` + `truncate(top_k)` already returns a
valid top-K set: the partition places the top `top_k + 1` elements in
`0..=top_k` and the truncate discards exactly the one extra element. Same
result set (tie choice at the K-th boundary aside — no test asserts ties; all
fixture scores are distinct). Both variants are O(N). The body's "restores
exact O(N) partial selection semantics" implies a defect that never existed;
the real change is one element less partition work.

## Additional findings

1. **AGENTS.md bench-evidence violation**: title says `perf(...)`, body claims
   an O(N) impact, attached criterion/flamegraph evidence: none. Same gap in
   the introducing PRs (#529, #605).
2. **Load-bearing comment invalidated, twice**: after #689, the rationale at
   `hybrid_tests.rs:177-179` ("Using `>=` ... would call
   select_nth_unstable_by(top_k) with index == len and panic") is factually
   false — `>=` would now call `select_nth_unstable_by(top_k - 1)` with index
   `len - 1`, which is valid. The `>` vs `>=` mutation kill engineered in #529
   is silently neutralized, in both byte-identical test copies.
3. **Narrowed input domain, undocumented**: old form was safe for any
   `top_k >= 0`; the new `top_k - 1` underflows at `top_k == 0` and is only
   unreachable because of the early-return guard at
   `crates/csm-retrieval/src/hybrid.rs:202-204` — a guard the PR never
   mentions while stamping "Algorithmic Optimization" over the dependent line.
   Sibling sites use a plain `let nth = top_k - 1;` (`bm25.rs:381`,
   `rerank.rs:64,174`, `graph_rag.rs:90,186`, `lsh.rs:152`,
   `brute_force.rs:93`) with no banner comments.
4. **Formal review impossible**: the authenticated account (d-o-hub) authored
   #689, so GitHub rejects `--request-changes` on it ("Review Can not request
   changes on your own pull request"). The roast was posted as a PR comment:
   <https://github.com/d-o-hub/chaotic_semantic_memory/pull/689#issuecomment-5647680889>.

## Verdict

**REQUEST CHANGES (posted as comment)**: safe-but-pointless as-is. Blocking
asks: (1) fix the live root copy too (or delete the duplicated bodies per the
queued dedup action), (2) update the stale boundary-test rationale in both
copies, (3) attach criterion evidence from `benches/hybrid_benchmark.rs` run
against the fixed root copy (or drop `perf(...)` from the title), (4) match
sibling style (`let nth = top_k - 1;` + document the `top_k == 0` guard
dependency).

## Prevention

- **Sweep every workflow's latest run**, not just ci.yml — scheduled
  workflows can burn red for weeks while PR-time paths filters hide them.
- **Perf claims**: enforce the AGENTS.md criterion-evidence rule at review
  time; Jules `perf(...)` PRs recur without numbers (#529 → #605 → #689).
- **Dual-surface changes**: before judging a "fix", identify which copy
  production executes; the hybrid dedup is still owed (queued action
  family ADR-0094/0095).
- **Watch CI duration drift**: when median main-CI duration approaches the
  Release poll ceiling, raise it or migrate `wait-for-ci` to a
  `workflow_run`-triggered design.
