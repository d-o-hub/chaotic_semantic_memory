## #814 `perf(core-lib): early-return on 0-shift in HVec10240::permute`

**Verdict: CLOSED AS NO-IMPACT** (2026-10-03T11:15:46Z), roast comment
`pull/814#issuecomment-5968629895`.

Jules bot PR, +3/−0 in `crates/csm-core-lib/src/hyperdim.rs`: the same
`if word_shift == 0 { return *self; }` that **#800** carried, was roasted on
2026-10-01 (`plans/PR_ROAST_2026_10_01.md`), measured, and closed as no-impact
on 2026-10-02 (`plans/PR_ROAST_2026_10_02.md:53`). New task id, new branch
(`perf/hvec-permute-zero-shift-…` vs `perf/hvec-permute-fastpath-…`), identical
claim.

CI truth on head `700d4c1` (run 37101076220): every job green **except
`commitlint`**, which fails on this repo's own perf-evidence gate — the body
carries `What`/`Why`/`Impact` prose and no `## Performance Evidence` section,
which is what `scripts/check-perf-pr-evidence.py` reads for a `perf(...)`
title. `mergeStateStatus: BEHIND`.

Roast findings:

- **Refuted mechanism restated as fact.** The body claims "O(W) → O(1) register
  copy". `permute` returns `Self` by value (`hyperdim.rs:366`), so a 1 280-byte
  copy happens on every call either way — including through this early return
  (`return *self`). What the branch actually removes is the `[0u128; 80]`
  zero-init plus one redundant `copy_from_slice`: at `word_shift == 0`,
  `split_at(0)` makes the first copy a straight replay of `self.data`. One copy
  saved, not an asymptotic class.
- **Reachability is real but already measured at nil.** `encoder.rs:226`
  permutes `pos * position_stride`, so `permute(0)` fires once per `encode`
  (`pos == 0`). #800's numbers: direct call 81.7 → 57.3 ns (6/6 rounds), caller
  path `text_encoder/encode_short` 2 684 → 2 734 ns (3/6 rounds each way) —
  inside the run-to-run spread.
- **Strictly less complete than the closed predecessor.** #800 shipped the
  `hvec_permute` bench over `0` / `10240` / `10240 × 3` with `128` and `321`
  controls, and extended `test_permute` with both modulo-identity assertions;
  #814 shipped neither, no evidence, no `Fixes #`. History: 4 commits, 3 of them
  the same headline under two different scopes (`perf(core)` ×3,
  `perf(core-lib)` ×1).
- **Rule 17 applied** — a resubmission of a closed idea must bring the evidence
  the roast demanded, not re-post the claim. Both honest routes were left in
  the comment: a whole-`encode` delta outside the spread, or the caller-side
  `if pos != 0` skip at `encoder.rs:226`, which needs no branch in the hot
  function. Correctness was never in doubt — `hyperdim_tests.rs:48` already
  asserts `v == v.permute(0)`; it was closed on unmeasured impact.

### Verdict: **KEEP-WITH-CHANGES**, changes applied before opening

- **The honest failure mode of a config surface was avoided, and the record has to say how.**

  shipping dead validation that a later reader must re-derive.

## Lessons distilled (this round)

1. **Target-independent cargo features leak dependencies into wasm32 checks.**
   Gating a tokio feature on `cli` re-broke `validate.sh`'s
   `--target wasm32-unknown-unknown` stage because the default set enables
   `cli` there. Deleting a rationale comment that documents exactly this
   hazard re-introduced the hazard. Gate: after any dependency-feature change,
   run the wasm32 default-set check.
2. **Regenerate `llms.txt`/`llms-full.txt` in the branch that changes public
   doc comments.** The drift gate fails late in `validate.sh`, so it surfaces
   as the *second* red on a previously-fixed head (precedent: #801 shipped
   regeneration inside its change commit).
3. **Watch CI by run id verified from `gh run list`, not from memory.** A
   mistyped run id makes `gh run watch --exit-status` fail instantly while the
   orchestration shell still exits 0 — always re-read the conclusion from the
   run itself.
4. **Rebase bookkeeping PRs onto the exact new `main` and verify their own
   counters** — #812's count/comment pair became right-for-the-wrong-reason
   once #813 landed ahead of it.
5. **Search the roast records before treating a bot PR as new work.** One
   `grep -rn 'permute' plans/PR_ROAST_*.md` turned "green idea pending merge"
   into "already measured and closed as no-impact". Jules re-opens the same
   finding under a fresh task id and branch name, and the duplicate lives in
   `plans/` — an open-PR scan alone cannot see it. Corollary: a perf claim's
   *mechanism* sentence has to be checked against the code, not the CI; #800 and
   #814 both asserted a zero-copy win that a by-value `-> Self` return makes
   impossible.
6. **A green run on the right SHA can still be the wrong workflow.** The
   "CI green on `25a5948`" I reported before merging #812 was the **Tooling
   Guard** run (37118663547); the `CI` workflow for that head (37118663549) was
   still queued, which is why `mergeStateStatus` read `BLOCKED`. Diagnose a
   blocked PR with `gh pr view --json statusCheckRollup` and list pending
   contexts, and read run truth per `workflowName`
   (`gh run list --branch <head> --json workflowName,headSha,conclusion`), not
   per SHA.
7. **`BLOCKED` also means draft.** #812 stayed `BLOCKED` after every check went
   green because it was a draft on an unprotected trunk
   (`branches/main/protection` → 404, ruleset `required_status_checks: null`) —
   `gh pr merge` then said *"Pull Request is still a draft"* while
   `mergeStateStatus` had already flipped to `CLEAN`. Put `isDraft` in the same
   probe as `mergeable`/`mergeStateStatus` before concluding a blocker is
   branch protection.
8. **"Not breaking" needs the semver test, not the compile test.** A branch that
   compiles proves nothing about a *removed public trait impl* — dropping a
   `Clone` derive breaks downstream callers while the workspace still builds.
   Ask what a downstream `impl`/derive/signature the deleted type had is gone,
   then label it with the repo's `**Breaking (scope)**` changelog convention and
   a `BREAKING CHANGE:` footer. Corollary: check which notation the repo
   actually uses (`grep -cE '^[a-z]+(\([^(]+\))?!:' ` on `git log --format=%s`
   returned 0, so the CHANGELOG label — not a `!` header — is the convention
   here).
9. **A subagent's own PR gets the same roast as a bot's, and its numbers get
   re-measured.** #816 came back claiming 21 `arch_fitness` tests (actual: 8)
   and a blanket "not breaking" (actual: semver-visible). Re-run the gates that
   the report cites and count from the artifact (`grep -c '#[test]'`,
   `cargo test --test …` per target) — an implementer's summary is a lead, not
   evidence. Records PRs are also not exempt from a verdict section: this round
   merged #815 without writing one for it, which is why #816's verdict is
   recorded inside the PR it reviews.
10. **Deleting a duplicate deletes its prose.** The collapsed builder's `with_ttl`
    doc held the one sentence explaining that expiry is resolved at `build()`
    time, not at setter time; the owner's doc did not. Diff a duplicate pair in
    *both* directions before removing either side — comments and rationale
    included — and port the rationale first (same rule as the 2026-09-18 facade
    finding, now applied to docs instead of fixes).
11. **When a warning becomes an error, "which line broke it?" is the wrong question.**
    The Pages outage was not caused by the diff on the failing push: the offending doc
    text landed in `b4bed50` and stayed a *warning* for weeks, and `aa4f9ab` — a
    Dependabot bump of `actions-rust-lang/setup-rust-toolchain` v1.17.0 → v2.0.0, the
    action that exports `CARGO_BUILD_WARNINGS=deny` — promoted it. Diff the **workflow
    and tool versions** across the green→red range (`git log <green>..<red> --
    .github/workflows/<file>`) before reading the code diff. The reason it could rot
    across five pushes: a compile step no *required* check runs is not a gate —
    `cargo doc` appears only in Pages, and `clippy --all-targets` does not build
    documentation, so CI stayed green while the deploy died. Mirror every
    non-required workflow's compile step into `validate.sh`.
12. **The orchestrator's own numbers in a dispatch brief get re-measured too.** I told
    the implementer `src/cli/mcp.rs` was 479 LOC and ordered an extraction; it is 21
    (the Explore agent's `21 (479)` was a table cell, and I read it as a delta). The
    implementer re-measured, flagged the deviation in its report and skipped the
    unnecessary step — the behaviour a brief should invite, not forbid. Same rule as
    lesson 9, pointed at myself.
13. **A missing `#[test]` is invisible to every gate in this repo.**
    `tests/cli_parity.rs:97` has no attribute: `-- --list` registers 2 of the file's 3
    test bodies, `cargo test` reports success, and recompiling emits **no** `dead_code`
    warning — rustc's reachability analysis in a `--test` build ignores a private fn
    that only the harness would call. So "it compiles" and "the suite is green" say
    nothing about whether a test exists; the only detectors are counting harness
    entries or counting attributes, and the queued action has to add one.
14. **A `MISSED` from cargo-mutants can be a statement about the profile, not the tests.**
    Before writing a kill-test for a survivor, check that the job compiles the line:
    feature-gated code under a default-feature profile is reported MISSED, and the score
    cannot tell "the tests are weak" from "the file was never built". `cargo test --lib
    -- --list | grep -c <module>` with and without the feature is the whole diagnosis in
    two commands. Corollary: a new feature-gated module must be added to the mutation
    profile's feature set, or recorded as never mutation-tested — otherwise the gate
    reports silence as failure. And when widening a gate's feature set, budget the cold
    base build *before* pushing (raise the bound **and** pre-warm it): 150 s was generous
    for a 54 s incremental rebuild and impossible for a 146–183 s feature link.
15. **Read the test you cite as coverage — then ask whether the line is reachable at all.**
    My own comment claimed the ADR-0099 shutdown-on-transport-end "is asserted" in
    `tests/mcp_sse_integration.rs`; that test calls `serve` and then `abort()`s the task, so it
    can observe nothing after the awaited transport — and on SSE nothing ever follows it, because
    axum 0.7.9's `Serve` future accepts forever without `with_graceful_shutdown`. Citing a file
    that touches a function is not citing an assertion on its effect (the same distinction that
    made #817's reaper tests trustworthy: they assert raw stored rows, not config echoes), and an
    *unreachable* line is a different finding from an untested one: no test, mutation or otherwise,
    can ever express it. So when a gate goes silent about a line, the last question is the
    dependency's own source — the answer can be a production defect in a PR that already merged.
16. **`git fetch` is part of "branch first", and `git diff --stat origin/main` is part of "open
    the PR".** A pure-records branch cut from a stale local `origin/main` carried a diff that
    deleted the previous PR's source files (`src/cli/mcp.rs −68`, `scripts/mutation_test.sh −64`)
    — and nothing in the pipeline objects to that: the pre-push hook runs clippy + fmt, commitlint
    reads subjects, and `mergeable` says `MERGEABLE` because the *content* conflict is with commits
    that are already ancestors. The audit of the parallel parity branch found the mirror image of
    the same bug class (2 real commits riding 11 replayed #817 commits, silently un-roasting
    #817's records), so this is not one careless rebase but the failure mode of trusting a ref
    you did not just fetch. Gate: before a PR body is written, read the diff **stat** against the
    fetched `origin/main` and reject any file outside the PR's declared scope.
