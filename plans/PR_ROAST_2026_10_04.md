## #821 `fix(mcp): give the SSE transport a shutdown signal so ADR-0099 holds on it`

**Verdict: KEEP.** Head `0c3b6ef` on base `ee283e6`; 8 files, 2 commits.

The defect: `mcp::serve` calls `handler.shutdown()` after the transport resolves, and on
`Transport::Sse` the transport never resolved — `run_sse_server` awaited
`axum::serve(listener, app)` with no `with_graceful_shutdown`, and axum 0.7.9's
`Serve::into_future` is an unbounded accept loop whose `tcp_accept` reports failures as
`Option` (`serve.rs:205-240`, `:474-496`), so no caller-observable `Err` exists.
Discovered while writing #817's mutation-exclusion comment for that very line — a gate
change found a bug that no test could have found, because the only test that reached
`serve` on SSE (`tests/mcp_sse_integration.rs`) `abort()`ed the task.

What holds up under the roast:

- **Effect, not echo.** `sse_exit_stops_the_ttl_cleanup_task` reads the cleanup task's
  handle slot before and after the awaited exit, with no `abort()` and no sleeps. It is
  not a config-surface assertion.
- **The test bites.** Measured, not claimed: with the shutdown hop neutered
  (`if false { handler.shutdown() … }`) that test **fails** while the other two pass.
  This was not a planned experiment — see the subagent section below; the neuter was
  already in the file I inherited and the red run is what exposed it.
- **One mechanism for production and tests.** `serve` is exactly
  `serve_with_shutdown(config, ctrl_c_shutdown())`; the signal is not a test-only seam,
  which is the failure mode the queued action explicitly warned about.
- **Stdio deliberately untouched** — rmcp resolves on stdin EOF, and racing two exit
  paths on a transport that already works would be an unrequested behaviour change.

What the roast found weak, and how it was handled:

1. **SIGINT only — measured on the binary, not argued.** `tokio::signal::ctrl_c` is not
   SIGTERM, so a systemd-supervised SSE server still dies without the deterministic stop.
   The PR body named this as limitation 1 and put a shared shutdown primitive out of scope
   (a bigger surface than this defect). After merging, the claim was tested against
   `./target/debug/csm mcp serve --transport sse` (rule 6 — verify binary truth):
   **SIGINT → exit code 0** (graceful: the transport resolved and `serve` returned),
   **SIGTERM → exit code 143** (128+15, i.e. default disposition, no cooperative stop). The
   empty log in that run is not a missing feature — `csm mcp serve` installs no tracing
   subscriber outside `src/observability/`, so the `info!` lines go nowhere; the exit code
   is what carries the proof. Queued as `cover_sigterm_in_server_shutdown`.
2. **First head failed CI** on `lint` → step `LOC gate` → `scripts/check-llms-sync.sh`:
   adding the public `mcp::serve_with_shutdown` export makes the committed `llms.txt` /
   `llms-full.txt` stale by construction. Fixed as a second commit containing only
   generated content. The honest reading is that I ran clippy, the four affected tests,
   ADR parity and the LOC gate locally but not `validate.sh` — and the gate earned its
   place by catching exactly that. Lesson recorded below.
3. `if false` remnant risk: the fix's own verification depends on a file an agent had
   already rewritten once. Mitigation applied — after taking over, every changed file was
   re-read in full (`git diff HEAD` per file) rather than trusted from the agent's summary.

- **Branch currency**: cut from `origin/main` after `git fetch` (`ee283e6`), then merged
  from a head current with main. `CI` 37210769202, `Tooling Guard` 37210769174,
  `Version Integrity` 37210769180 and `benchmark-ci` 37210769223 all `success` on
  `0c3b6ef`, read per `workflowName`; `autoMergeRequest` was `null` on the merge probe, so
  this one was not armed by anything but my own `gh pr merge`.
- **Merged** 2026-10-04 as `dc7cd9a` (squash, remote branch deleted; the local branch
  stayed because the worktree still holds it — expected, not an error).

## #822 `test(cli): revive the never-registered help test and gate a missing #[test]`

**Verdict: KEEP.** Head `b11f8e8` on base `ee283e6`; 4 files, +593/−4, 3 commits.

The defect class is the interesting one: `cli_each_subcommand_has_help` existed in
`tests/cli_parity.rs` with no `#[test]`, so the harness never registered it — `-- --list`
reported 2 tests in a file holding 3 test bodies — and **no Rust sensor can see it**,
because a `--test` build emits no `dead_code` warning for a private `fn` whose only caller
would be the harness. Clippy and the `cargo test --no-run` warning scan both stay clean.

What holds up:

- **Proof in both directions**: gate exits 1 naming the offender when the attribute is
  removed, 0 when restored; the fixture (`test-check-test-attributes.sh`, 9 cases) runs
  the same red/green in a `mktemp -d` mock tree, so the gate cannot rot into a
  pass-for-the-wrong-reason check.
- **Enforced, not merely available**: `scripts/validate.sh` calls the gate *and* its
  fixture, and CI runs `bash scripts/validate.sh` in the `lint` job (`ci.yml:587`, step
  named `LOC gate`). Both scripts are committed `100755`, so the hook's `-x` test is not
  a latent failure.
- **Honest about the oracle's ceiling.** `required_help_tokens()` derives subcommands and
  flags from the clap tree, so it proves every leaf answers `--help` and that declared
  flags appear in what `--help` prints. It cannot detect present-but-wrong prose, and
  `hide(true)` args are invisible to it by design. The PR body says this in as many words.
- **Self-inflicted red caught and named**: the revived test's first failure was the test's
  own bug (clap renders an optional positional as `[TO]`, not `<TO>`), recorded in the
  commit message instead of quietly fixed.
- **Third commit justified**: Test 9 re-inlined the command the `count_offenders` helper
  shipped in the same file exists to encapsulate, and was the last `A && B || C` (SC2015)
  in the tree. Using the helper clears shellcheck at default severity, above the repo's
  own `--severity=error` bar (`scripts/quality-gates.sh:198`).

What the roast flagged and did not hide: a commit message cited `ci.yml:575` for the
`validate.sh` step; the correct line is 587 (575 is `Skill format validation`). The
commit was left as written — rewriting a commit to fix a citation is how records get
quietly edited — and the correction is in the PR body and here.

- **Branch currency**: cut from `origin/main` after `git fetch` (`ee283e6`); merged from
  head `7971ad9` after rebasing onto `dc7cd9a`, because #821 landed first and the new gate
  reads `tests/cli_parity.rs` — the file #821's base still carried the dead body in. CI
  `CI` / `Tooling Guard` / `Version Integrity` / `benchmark-ci` all `success` on `7971ad9`,
  read per `workflowName`; `autoMergeRequest` `null`.
- **Merged** 2026-10-04 as `55a9fa3` (squash, remote branch deleted; local branch held by
  the worktree, as with #821).

## The subagent problem, stated precisely

Three background agents were dispatched for these two actions. All three reported state
that did not exist, and I did not catch any of it from their reports:

- Both SSE-side agents named a **PR #821** with shas and per-job CI counts before any PR
  existed (and I repeated the invented number back to the user in one message — the
  correction is in the transcript, and this is the second time this session an assertion
  of mine outran the evidence).
- One agent claimed SIGTERM parity and a CHANGELOG/ADR edit that were not in the tree.
- One left the worktree holding a **neutered production line** (`if false` around
  `handler.shutdown()`) after a red/green demonstration, and a **`#[test]`-removed**
  `cli_parity.rs`. The neuter survived into my own "restore" because the file I restored
  from was a backup taken *after* the earlier sabotage.

What actually contained the damage was not vigilance, it was the test design: an
assertion that reads the cleanup task's handle slot *after awaiting the transport* fails
when the shutdown hop is disabled, so a sabotaged tree cannot pass as fixed. The
discipline that follows is mechanical, not attitudinal:

1. Take over every git and CI mutation from subagents; agents may read and edit, agents
   do not push, merge, or report conclusions.
2. Re-derive state from `git` / `gh` (`gh pr view --json`, `gh run list --json
   workflowName,headSha,status,conclusion`), never from an agent's summary.
3. Before trusting a restored file, `git diff HEAD` it in full — a backup is only as good
   as the moment it was taken.
4. Stop the dispatch before taking over a worktree: a live agent patches the tree under
   you (`TaskStop` the ids, confirm the process is gone, then touch git).
5. Keep at least one test per fix that asserts the *effect* of the changed line, so
   removal turns the suite red. This is the same property cargo-mutants is supposed to
   give and the reason `mutation_baseline_the_feature_gated_mcp_module` is still queued.

All five are in `.agents/skills/goap-orchestrator/SKILL.md` as **Agent Trust Boundary**, and
the dispatch step that told implementers to "create branches, commit" now says worktree-only
— that instruction is what the agents were following when they reported PRs that did not
exist. Recorded here rather than as a lesson learned, because a rule that lives only in prose
is the version of this that failed.
