### Correctness — sound, re-verified by measurement

- **Reading.** `selected.push(best_cand)` sits *after* the update block, so at the guard
  `selected.len()` is the pre-push length (`i - 1` on iteration `i`) and
  `selected.len() + 1 < top_k` is exactly "the loop will run again": after the push the length is
  `i ≥ top_k`, so the loop cannot continue. The skipped update's cache is therefore never read
  and the output is identical. Degenerate inputs: `N ≤ k` saves `0` sims, `top_k = 1` saves the
  whole update pass (`N - 1`) — no regression branch anywhere. The `!candidates.is_empty()`
  clause is operationally redundant (the zip over an empty slice is a no-op); keep it only as
  intent, ideally by naming the predicate after the loop condition.
- **Test coverage is real.** Mutating the guard to the stale-cache direction
  (`selected.len() + 2 < top_k`, which also skips the `i = k-1` update) fails
  `cargo test -p csm-retrieval --lib` — 2 of 58:
  `rerank::tests::test_mmr_reranker` (`rerank_tests.rs:56`, `results[1].id`) and
  `rerank::tests::test_mmr_lambda_zero_score_is_negative_after_first_selection` (`:193`).
  Control with the guard restored (marker instrumentation still compiled in): 58 passed,
  0 failed. The framework pipeline test (`framework_rerank_tests.rs:60`) does **not** catch it:
  `probe_with_rerankers` (`src/framework_rerank.rs:55`) passes
  `actual_initial_k = max(initial_top_k, final_top_k)` to `rerank` and truncates to
  `final_top_k` afterwards, so a changed 3rd pick is discarded.
- **Mutation gate caveat.** The added condition's cargo-mutants-visible mutants are *equivalent*
  (skip nothing / always skip — both unobservable), so a green `mutation-test` job cannot be
  evidence for this guard; the dangerous direction above is what the lib tests pin, and the
  optimization itself can only be evidenced by a benchmark.

### Impact — real, but unmeasured in the PR, and the only in-repo comparator is blind

**The bench cannot see the change.** `benches/rerank_benchmark.rs:19` prefills candidate 0 with
`score = 1.0 - (i/n) = 1.0`, and `rerank` early-returns when `candidates.first().score >= 0.99`,
so all six `mmr_rerank/*` + `mmr_rerank_pure/*` ids time the fast path only. Marker-verified in a
scratch worktree (env-gated `Once` `eprintln!`): `fast_path` printed for every original id,
`slow_path` only after prefilling scores below 0.99. This is the #763/#800 class of trap, and it
is exactly the id #891 cited.

**Measured here** (the `canonical.json` reference CPU, `taskset -c 2`, 40 samples × 4 s,
alternating legs; a foreign `cargo-nextest` build held ~7 `rustc` processes during the run):

| bench (throwaway reparameterized, `N = 500`) | leg 1 | leg 2 | leg 3 | leg 4 |
|---|---|---|---|---|
| `mmr_rerank_slow_k1/top1_from_500` (`k = 1`) | −34.6 % (p 0.00) | +79.5 % base-vs-head (p 0.00) | −36.9 % (p 0.00) | +46.5 % base-vs-head (p 0.00) |
| `mmr_rerank_slow/top10_from_500` (`k = 10`) | −8.8 % (p 0.00) | +41.5 % base-vs-head (p 0.00) | −17.3 % (p 0.00) | +4.9 % (p 0.42, contaminated) |

Leg 4 of the `k = 10` set is contaminated (both variants ~1.0–1.1 ms, ≈ 2.4× the clean legs,
p = 0.42) and is named and excluded rather than averaged in. `k = 1` medians: base
85.7–95.3 µs vs head 51.8–55.6 µs (≈ 40 % faster) ⇒ ≈ 64 ns per in-workload sim ⇒ 490 saved
sims ≈ 31 µs at `k = 10`, against 410–460 µs baselines; the clean `k = 10` legs read
−8.8 %/−17.3 % (criterion) with per-leg mean ratios −9.3 %/−12.9 %/−13.9 %, the same order. The
PR's "~9.9 % reduction in pairwise similarity operations" is correctly scoped to the update term
(4945 → 4455 of 5445 total sims); the missing piece is the *wall-clock* artifact, and it is
obtainable. Two control legs on the blind id read −3.5 % (p = 0.38) then +10.2 % (p = 0.01,
"regressed") — noise with no repeatable sign, on code the diff does not touch.

**Reachability.** No shipped binary in this repo calls the reranker: `grep -rni 'rerank'
src/cli/ crates/csm-cli/src/ src/mcp/` is empty, `parse_rerankers`' only callers are
`csm-retrieval` itself, and `probe_with_rerankers` has no non-test caller. The win lands on
**downstream library users** of the documented public API (`llms.txt:640–644`), not on any
in-repo product path — state that in the PR body so the value judgment is explicit instead of
implied by a percentage.

### Hygiene findings
