## #923 — `perf(retrieval): defer score normalization calculation in single list hybrid merge`

Jules PR, head `fba7121d`, base `main`, `mergeable: MERGEABLE`, CI red on the evidence gate:
`::error::perf PR evidence gate: missing `## Performance Evidence` section in the PR body`.
Closed with <https://github.com/d-o-hub/chaotic_semantic_memory/pull/923#issuecomment-6291823853>.

**1 — The gate is syntactic and the artifact did not exist.** `scripts/check-perf-pr-evidence.py`
checks that a `perf(...)` body carries a canonical baseline, an artifact path and a numeric
before/after pair. It cannot check that the cited benchmark reaches the changed code — the blind
spot #763 was closed for. Here it was worse than a wrong bench: **no bench in the repository
executes `merge_single_list`**, because every existing `hybrid` bench passes both result lists
non-empty and `merge_results` returns through the HashMap path first.

**2 — I built the missing bench rather than arguing from the code.** `benches/single_list_benchmark.rs`
(second list empty, `[[bench]]` registered on both sides of the A/B), N ∈ {100, 1 000, 10 000} ×
K ∈ {10, 20, 100}, four interleaved base→PR rounds, each row paired inside its own round.

| row | median | rounds slower |
|---|---|---|
| N100_K10 / K20 / K100 | +3.8 % / +5.4 % / **−13.2 %** | 1/2 · 3/4 · **0/4** |
| N1000_K10 / K20 / K100 | +10.5 % / +5.7 % / +5.9 % | 3/4 · 3/4 · 3/4 |
| N10000_K10 / K20 / K100 | **+25.4 % / +24.0 % / +21.5 %** | **4/4 · 4/4 · 4/4** |

**3 — The only win is in the configuration where the optimization is inert.** At `N100_K100`,
`ref_results.len() > top_k` is false, so `select_nth_unstable_by` and `truncate` never run and
nothing is deferred: that −13.2 % is the incidental `map().collect()` → `with_capacity` + push
rewrite, not the claimed arithmetic saving. #763 set the bar as "a consistent sign across N and K —
not the best row"; the sign is consistent and negative.

**4 — Deliberately not "fixed" by writing the evidence section.** A well-formed section would clear
the gate, and the numbers available say *slower*; dressing a regression up to satisfy a shape check
is worse than no check. Retitling `perf` → `refactor` to dodge the gate is gate-gaming and also not
done. What survives the close: the **top-k parity test** (an order-preserving min-max scale may be
deferred past selection without changing results) and the **`k >= n` guard** are real invariants
worth landing as `test(retrieval)` / `fix(retrieval)`, with no perf claim attached.

**The `>=` kill is the non-obvious one, and it failed once before it worked.** Two separate reasons:

- *Blind observable.* Expansion scores are min-max normalised, so a **single** retained label the
  anchor does not resemble leaves every existing hit at `0.0` — identical to correct behaviour. The
  test expands `alpha` + `gamma` against an anchor encoded from `"alpha gamma hub"`, so a retained
  set scores `1.0`/`0.96` and the mutant's failure names itself:
  `[("mem-1", 0.0), ("alpha", 1.0), ("gamma", 0.9599359)]`.
- *The boundary was never reached.* `expires_at` is second-granular and both sides read the same
  `unix_now_secs()`, so a TTL built back-to-back with the query usually observes `now == expires + 1`
  — where `>=` behaves exactly like `>`. `aligned_harness` waits for a fresh second, builds with
  `with_ttl(0)` so `expires_at` lands on the second being sampled, then asserts the *sample count*:
  an unaligned run fails as a broken precondition instead of silently passing.

Kills were produced by editing each source line and re-running the target, not by a 24-minute
`cargo-mutants` pass, so CI remains the authority on the score. Locally: 5/5 killed, baselines green,
`cargo test --features persistence --lib` 186 passed / 0 failed, fmt clean,
`cargo clippy --all-targets -D warnings` clean, boundary test repeated 5× with no flake (~1.6 s).
`src/bridge_retrieval_tests.rs` sits at 499 lines, so the coverage went into a sibling module rather
than more lines under the 500-LOC gate.

**Two defects the pushed head exposed, both mine.** (a) `docs(llms): catalogue the bridge expiry test
module` used scope `llms`, which `commitlint.config.cjs` does not allow. My local pre-push check ran
`npx commitlint ... | tail -15` and I read **`tail`'s** exit code, not commitlint's — the real exit was

(b) The **miri** job failed on the boundary test: `could not resolve every ttl-0 expiry onto the second
the harness was built in`. Miri simulates the clock, so `sleep` never moves `SystemTime::now()` the way
wall time does and the alignment loop cannot land on the expiry second — a test that was correct about
a real clock and meaningless about a simulated one. Fixed forward in `b4cacbf4` with
`#[cfg(not(miri))]` on the test and on its helper (the other two expiry tests passed under miri and
still kill `==` and `<`).
