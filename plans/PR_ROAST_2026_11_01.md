## #977 — the premise is real here, and one kernel loses

The `MaybeUninit` zero-init family has been closed twice by this repo (#783, #893, #950),
so the prior verdict is *not* inherited — the skill's rule cuts both ways: a predecessor's
verdict does not transfer to a new site, and neither does its refutation.

**Disassembly (x86_64, rustc 1.88.0, `-O -C codegen-units=1`, `#[no_mangle]
#[inline(never)]`, old and new linked into one binary).** At this site the old body is
*not* dead-store-eliminated:

```
and_avx2_old / bind_avx2_old:  sub $0x500,%rsp ; … ; call *memset@GLIBC_2.2.5
                               vmovups/vandps loop writing all 40 × 32 B
bind_x86_old:                  call memset(0x500) ; vector loop storing straight into sret
and_avx2_new / bind_avx2_new:  no memset at all
bind_x86_new:                  no memset, but stack stores + memcpy(0x500) into sret
```

The reason is the store shape: the loop writes through a computed pointer
(`res.as_mut_ptr().add(i)`), which defeats the full-coverage proof DSE used in
`hyperdim_binary.rs`. So the claimed 1 280-byte zero-fill exists **here** and does not
elsewhere — the #783 result is site-specific, and so is this one.

**Correctness**: bit-identical. The probe asserts `old == new` for `and_avx2`, `bind_avx2`
and `bind_x86`; no mismatch.

**Impact** (interleaved `A/B/A/B`, same binary, no rebuild between legs, `black_box` on the
return like criterion does, 200 000 iterations, load 1–2):

| kernel | old | new | delta | rounds new-faster |
|---|---|---|---|---|
| `and_simd_avx2` | 69.09 ns | 54.23 ns | **−21.5 %** | 4/4 |
| `bind_simd_avx2` | 68.86 ns | 53.23 ns | **−22.7 %** | 4/4 |
| `bind_simd_x86` | 72.74 ns | 76.62 ns | **+5.3 %** | **0/4** |

The PR's −16.9 % sits inside the AVX2 range, so the claim is supported. `bind_simd_x86`
is a regression for a structural reason visible in the disassembly above: the old body
wrote directly into the return slot after the memset, and the new one writes a stack
buffer and then copies 1 280 bytes back. A variant that keeps initialization at the
destination (`MaybeUninit::<V>::uninit()` + `ptr::write`, `assume_init`) does **not**
reliably recover it: −1.3 / +2.5 / −0.1 / +4.8 % against the PR form, no consistent sign.

**Bench blindness, fourth kind — by dispatch arm.** `hvec_bind` is
`a.bind(black_box(&other))`; on any AVX2 host it enters `bind_simd_avx2` and can never
reach `bind_simd_x86`. The cited evidence therefore cannot show the regression the diff
introduces, and no input distribution fixes that — only diffing every changed `cfg` arm
does. Recorded in `references/bench-blindness.md`.
