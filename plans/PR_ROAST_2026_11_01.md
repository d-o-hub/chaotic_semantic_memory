## #978 — merged, and the two things that had to be checked first

#978 scopes mutation discovery to the packages the diff touches. Two things were alleged
by its own description and neither survived hunk inspection:

1. *"rationale comments deleted"* — the diff was read per hunk, not per file stat: the
   surviving `#9xx`/ADR tags are all still present, and what left the file moved into the
   fixture that now proves the same behaviour. Rule: a comment-count diff is a lead, not
   evidence (`Never delete rationale comments` is about *deleting the reasoning*).
2. *"the fixture passes in CI"* — the `mutation-test` job is path-filtered and did **not**
   run for this diff. The green came from the `lint` job, which invokes the fixture
   directly. Reading the badge instead of the job would have accepted a claim about a run
   that never happened.

Both corrections are the reason the merge happened after a rebase-then-CI cycle rather
than on the stale head.

## #949 — the premise that was half wrong

The issue says host subprocesses inherit a leaked `LD_LIBRARY_PATH` from `nix develop`
and proposes pinning the Ubuntu runner image. Measured:

- `scripts/run-with-libs.sh:9` is the **only** `export LD_LIBRARY_PATH` in the tree; the
  flake's `devShell` exports nothing and ships no `git`/`curl`.
- An **unwrapped** `nix develop --command cargo deny` step is the control that falsified
  the image theory: the `ubuntu-24.04` pins failed the identical line and were reverted.
- The leak site the issue describes was already scrubbed before this branch existed.

So the durable content is not a fix, it is a **sensor**: `scripts/check-nix-git-env.sh`
audits every `nix develop` step body (260 lines, 6 jobs, 14 lines, 3 wrapped entrypoints),
probes each regex against a known positive *and* a known negative before believing a zero,
treats "the audit could not run" as exit 2 instead of a verdict, and refuses to report
clean when a wrapped step execs a script the tree cannot read. Its fixture
(`scripts/test-check-nix-git-env.sh`, 37 cases) was proven sharp by neutering: 8/8
directions turn red, and an empty *wrapped-script list* fails rather than passing.

## #964 — re-measuring the issue's own number

Issue text: "16 pins are stale and `verify-version-sync.sh` exits 0". Re-measured on
`cae70539` in a throwaway worktree:

```
26 path edge(s) to workspace members; 18 stale
DRIFT: fuzz/Cargo.toml [dependencies] chaotic_semantic_memory declares "0.3.7" but the package is "0.3.9"
$ bash scripts/verify-version-sync.sh   →   ✓ All local versions synchronized: 0.3.9
```

16 → 17 → 18 as the enumeration widened, each step a different blindness:

| count | what was missed |
|---|---|
| 16 | single-line `{ path = …, version = … }` forms only — the issue's own method |
| 17 | `fuzz/Cargo.toml`, whose pin is a **multi-line** `[dependencies.chaotic_semantic_memory]` table |
| 18 | `benchmarks/Cargo.toml` — a declared root `[workspace]` member that no `crates/*` glob reaches; it shipped **three releases behind** at `0.3.6` |

The cause of the drift surviving at all is that `version = "0.3.8"` means `^0.3.8`, which
0.3.9 satisfies: Cargo resolves correctly, every test passes, and nothing is *broken*. The
cost is deferred to the first 0.4.x publish, where 7 of the 9 crates.io artifacts would
ship a manifest asserting a false compatibility floor. `Cargo.lock` records resolved
versions, not requirement strings, which is why pin rewrites cause no lock churn and why
the lock-based gates never noticed.

Delivered: `scripts/workspace-version-edges.py` — **one parser** behind `--list`,
`--check` and `--sync`, so the writer and the gate cannot disagree about what a pin is
(the class of bug the old split between `sync-version.sh`'s root-only sed and
`verify-version-sync.sh`'s root→member grep embodied). tomllib cross-checks the line
parser on the edge set **and on the version value**, and any disagreement is exit 2, not a
pass — the single-quoted `version = '0.3.8'` case is valid TOML that a `"` regex cannot see,
and it now stops the audit instead of reading clean. Discovery runs through the git index,
so a new member is audited without editing the tool; when no index exists the run says so
on stderr rather than quietly narrowing its own scope.

Sharpness, measured by neutering (not asserted):

- `scripts/test-workspace-version-edges.sh` — 54 cases, 0 failures; 9/9 tool mutations turn
  at least one direction red (dev-dependencies unseen, drift never reported, silent-pin
  cross-check removed, `refuse` exits 1, index discovery removed, `--sync` does not write,
  member filter removed, multi-line table entries ignored, `git ls-files` genuinely broken).
- `scripts/test-version-sync.sh` — extended from 4 tests to 9. Its first run **failed** on
  the existing mock: the verifier now needs its sibling tool, which the fixture had never
  had to ship. Two mutations initially escaped (exit 2 downgraded to a pass; `crates`-only
  member glob), so tests 7 and 8 were added for exactly those directions; 6/6 verifier
  mutations now fail the fixture.
