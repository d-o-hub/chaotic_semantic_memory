## #988 `chore(deps): bump uuid from 1.26.1 to 1.29.0 in /fuzz` — verdict: **close, no reachable impact**

Two failing checks, two different causes, and only one of them is the bump:

| check | job | cause |
|---|---|---|
| `lint` | 125310066544 | **inherited**: `STALE: action 'gate_the_effective_squash_subject_length' … #965 … CLOSED` — the same queue block that reddened `main`, retired on `main` by #990. The rebase clears it; it says nothing about this diff. |
| `Fuzz Workspace Build` | 125320036721 | **fatal**: `error: rustc 1.88.0 is not supported by the following package: uuid@1.29.0 requires rustc 1.89.0` |

The ceiling is not a guess. Read from the registry index on 2026-11-03:

```
1.26.1 rust_version = 1.85.0     <- locked today in both Cargo.lock files
1.27.0 rust_version = 1.89.0
1.28.0 rust_version = 1.89.0
1.29.0 rust_version = 1.89.0
```

`rust-toolchain.toml` pins `channel = "1.88.0"` and `Cargo.toml` sets `rust-version = "1.88"`, so the
bump cannot compile in this repository at any commit, and after pinning back to 1.26.1 the PR's diff
is empty. It is not a "nice-to-have blocked by flake"; it is an update whose only possible outcome at
this MSRV is a red job.

**Action taken:** comment with the job id and the index measurement, close, and encode the ceiling as
a commented `ignore` for `uuid` **minor** updates in both cargo ecosystems of `.github/dependabot.yml`
(patches still arrive). The comment names the removal condition — MSRV ≥ 1.89 — so the ignore cannot
silently outlive it. No MSRV bump is bundled here; that changes every build and deserves its own PR.

A local probe does **not** catch this class: `scripts/check-fuzz-lock.sh` runs
`cargo metadata --locked`, which read #988's lock without complaint (measured rc=0 in a worktree at
the PR head, rustc 1.88.0). Only the compiling job — `cargo check --manifest-path fuzz/Cargo.toml
--all-targets --locked` — sees it.
