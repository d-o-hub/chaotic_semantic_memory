## #998 — `fix(chaos): bound LSH input dimension and reject oversized requests` (Fixes #961)

**Verdict: LAND.** Rebased onto `fdc40ef4`, one real defect found and fixed in this session.

- **Atomicity:** one behavior — the `input_dim` contract on both LSH projectors. The intra-doc-link
  commit and the `no_std` test-build commit are fallout of the same change, not a second change; the
  `plans/` + `progress/` commit is the state-file retirement that AGENTS.md Phase 3 step 12 requires.
- **Impact is demonstrated:** before, `ChaoticLsh::new(100_000)` requested `10240 × 100_000 × 4 B`
  ≈ 3.8 GiB and `10240 * usize::MAX` overflowed the multiply. After, one shared `MAX_INPUT_DIM`
  (4096 → 160 MiB / 320 MiB per instance), a fallible `try_new` that rejects `0` and `> MAX_INPUT_DIM`,
  and an `input_dim()` accessor so a clamp in the infallible `new` is detectable. It answers every
  numbered requirement the issue set, including requirement 4: the hazard test asserts what
  `project()` **returns** for a mismatched shape, not merely that the clamp happened.
- **Title honesty:** "bound … and reject oversized requests" matches the split contract exactly
  (`new` clamps, `try_new` rejects). A title claiming "rejects oversized input" alone would have
  lied about `new`.
- **Scope:** `chaos` is in `commitlint.config.cjs` — which is the rule #956 died on (`hyperdim`).
- **Not bundled:** no `deny.toml`, no lockfile, no `export.json`, no perf claim, so the ADR-0095
  evidence gate does not apply.
- **The defect this PR carried into CI, and what it exposes about its own verification block:**
  the body's `## Verification` ran `cargo test -p csm-chaos --lib --features experimental-voronoi-lsh,std`
  — with `std` on. `csm-chaos` has `default = []`, so the crate is `no_std` unless asked otherwise,
  and `ToString` is not in the test prelude there. `zero.to_string()` at `hashing/mod.rs:92` failed to
  compile, and `lint` and `mutation-test` went red on the same single cause. The command that would
  have caught it before pushing was the default-feature build. Same class as the rustdoc lesson in
  `progress/LEARNINGS.md` for this issue: a scoped verification command can be green over the exact
  defect the workspace-wide gate rejects.
