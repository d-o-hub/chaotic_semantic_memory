### 2. Redundant / Non-Existent Allocation Mechanics
- `concept_ids.iter().map(|id| (*id, 0)).collect::<Vec<_>>()` in std already pre-allocates exact capacity
  (`concept_ids.len()`) via `Iterator::size_hint` / `TrustedLen`. Replacing `.collect()` with
  `Vec::with_capacity(...)` + `.extend(...)` produces identical heap allocations and capacity.
- In Rust's stdlib (hashbrown), `HashSet::new()` performs zero heap allocation until the first insert
  (it references a static empty table).
- `HashSet::with_capacity(concept_ids.len() * 2)` forces immediate heap allocation based on an unverified
  heuristic (`* 2`), increasing memory overhead for sparse graphs without demonstrable throughput benefit.
- `ConceptGraph::expand` immediately performs owned string allocations (`.into_iter().map(str::to_string).collect()`)
  for every returned label, which dominates latency.
