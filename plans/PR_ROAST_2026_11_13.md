## #1032 — premise verified against the failing job, not the diff

The PR exists because the floating `stable` toolchain moved to Rust 1.100.0 and its new *manifest*
lints became hard errors in the `stable-toolchain` job (`actions-rust-lang/setup-rust-toolchain`
exports `CARGO_BUILD_WARNINGS=deny`).

- Run `43403864562`, job `131813201776` (`Current Stable Rust Smoke`), exit **101** at
  `error: warnings are denied by build.warnings configuration`.
- Warning count read from the log's per-package totals, not eyeballed: **8** — `workspace (manifest)
  generated 4 warnings` (unused `edition`/`license`/`repository`/`homepage`), `chaotic_semantic_memory
  (manifest) generated 1 warning` (`cargo::redundant_homepage`), `csm-core-lib (manifest) generated 2
  warnings` (`bincode`, `rand_chacha`), `csm-retrieval (manifest) generated 1 warning` (`async-trait`).
- None of the eight came from the diff that job was scoring (#1031's SHA-validation change), so the
  canary was red for every PR in the queue, not for one branch.

### Findings raised by this roast

1. **The first push shipped a stale second lockfile.** CI run `43408922948`, job `131830225460`
   (`Fuzz Workspace Build`), failed in 29 s: `error: the lock file .../fuzz/Cargo.lock needs to be
   updated but --locked was passed to prevent this`. `fuzz/` is a separate workspace whose lock lists
   the dependency list of the path dependencies it reaches, so removing three dependencies from
   `csm-core-lib`/`csm-retrieval` invalidated it while the root `Cargo.lock` stayed correct. Fixed in
   the same commit (`fuzz/Cargo.lock`, −3 edges); `cargo check --manifest-path fuzz/Cargo.toml
   --all-targets --locked` passes. Rule distilled into the `git-workflow` skill (`Branch and
   Validation Gates`) and recorded in `progress/LEARNINGS.md`.
2. **The warning count was misstated as seven** in the commit body, the PR body and the two progress
   entries. Corrected to eight with the per-package breakdown. `scripts/check-fuzz-lock.sh` would have
   caught finding 1 locally in ~1.5 s had the full `validate.sh` run reached that stage.
3. **Residual warnings left in place, deliberately.** A whole-workspace host build at 1.100 also flags
   `csm-wasm`'s `chaotic_semantic_memory` (used only behind `#[cfg(target_arch = "wasm32")]`) and the
   root's `rand_chacha` (`examples/scale_evidence/util.rs`, a `required-features` example the default
   build never compiles). Both are live on the target that consumes them, so deleting them would break
   real builds; the lint is per target *and* per feature set. Out of scope, disclosed in the PR body.
