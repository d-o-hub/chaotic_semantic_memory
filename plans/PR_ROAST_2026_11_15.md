## Issue #992 — typed CI path selection (`crates/csm-ci-selection`)

**Premise, re-checked against the diff rather than the issue text.** `.github/workflows/ci.yml`
decided its seven `detect-changes` outputs with `git diff --name-only` plus `rg` pattern lists. The
`rust_src` list covered `src/**` and `crates/**` but not `src/cli/mcp.rs`, so a change touching only
the MCP CLI selected `cli_cross` + `docs` and left `mcp_feature` (and four other flags) false: the
MCP feature job never compiled or tested the file that changed, and the PR view showed it as a
skipped job, indistinguishable from a job that legitimately had nothing to do. Measured on the same
change set — `src/cli/mcp.rs` with no other path — main's expression yields `mcp_feature = false`,
the new selector yields true, which is the reproduction the acceptance suite keeps
(`tests/selection_acceptance.rs`, over real single-parent Git ranges).

**Verdict: KEEP — implement, and put the decision in tested code.** The defect is a real
false-negative in a required gate: the crate could regress while every ruleset context stayed green.
The classifier needs the same shape as the thing it protects — declared data, covered by tests, with
a stated reason per job. Shell functions inside a workflow cannot be run or asserted locally; the
same decision in a crate is exercised by `cargo test` in the `lint` job and in the matrix.

**What the re-created PR must carry.**
- The seven output names are unchanged — they are required ruleset contexts
  (declared in the branch ruleset — `gh api repos/d-o-hub/chaotic_semantic_memory/rulesets/<id>`;
  this PR renames none of them) — and every job the previous
  patterns could select is still selected.
- The classifier is fail-closed: unresolvable ref, failed diff, empty change set, unclassified path,
  a policy/`Cargo.toml` mismatch, or an ownership header that lists an unknown module each select
  **every** job, so an unclassifiable change costs CI time rather than skipping a gate.
- The crate is a workspace default member, so the assertions above run without a new CI job.
- The workflow keeps only range resolution; it carries no path patterns of its own, asserted by
  `tests/workflow_wiring.rs`.

**Evidence required in the PR body:** the measurement above (mcp.rs selects `mcp-feature`), the test
counts and the acceptance run over real ranges, the root-lockfile delta from adding the member, and
the local `./scripts/validate.sh` result. A claim in the diff without one of these stays out of the
body.
