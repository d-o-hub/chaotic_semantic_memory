# ADR-0046: npm OIDC Trusted Publishing Configuration

## Status

**Completed:**
- ✅ Phase 1: Workflow updated (NODE_AUTH_TOKEN removed, npm@latest ensured)
- ✅ Phase 2: Manual first publish (v0.1.0 published to npm on 2026-02-20)
- ✅ Phase 3: Verified package exists (via Snyk and API)

**Pending (blocked by token):**
- ⏳ Phase 4: Generate fresh npm automation token (current one expired)
- ⏳ Phase 5: Configure Trusted Publisher in npm UI
- ⏳ Phase 6: Verify CI publishing with OIDC

## Context and Problem Statement

The npm-publish.yml workflow uses `${{ secrets.NPM_TOKEN }}` but this secret has expired. The v0.1.0 npm publish succeeded (confirmed via Snyk showing v0.1.0), but subsequent CI runs fail with:
1. **"Access token expired or revoked"** - NPM_TOKEN secret is expired
2. **"404 Not Found"** - OIDC fallback fails because Trusted Publisher not configured

| NPM_TOKEN fallback | ✅ Done | For initial publish |

| Trusted Publisher configured | ❌ Pending | Requires fresh token |
| Package exists on npm | ✅ Done | v0.1.0 confirmed |

**Key Learnings:**
- Package name uses **underscore**: `@d-o-hub/chaotic_semantic_memory` (NOT hyphen)
- npm registry URL: `https://registry.npmjs.org/@d-o-hub_chaotic-semantic_memory`
- OIDC requires Trusted Publisher config AFTER package exists
- Token must be fresh automation token from npmjs.com/settings/tokens

## Decision Drivers

- ADR-0039 commitment to OIDC (no long-lived secrets)
- npm classic tokens deprecated December 9, 2025
- Automatic provenance attestation for supply chain security
- Zero token rotation burden

## Considered Options

### Option 1: Manual First Publish + OIDC Bootstrap (Chosen)

Manually publish first version from local machine, then configure OIDC.

**Pros:**
- No secrets ever stored in GitHub
- True OIDC from day one
- Cleanest security posture

**Cons:**
- Requires local publish access to npm
- Manual step for first version only

### Option 2: Temporary Token Bootstrap

Create short-lived token for first publish, then remove and configure OIDC.

**Pros:**
- Fully automated first publish
- Works from CI immediately

**Cons:**
- Temporary secret management
- Token must be revoked after

### Option 3: Skip npm Publishing

Defer npm publishing until manual setup is complete.

**Pros:**
- No rush
- Focus on crates.io first

**Cons:**
- WASM users cannot install from npm

## Decision Outcome

**Option 1: Manual First Publish + OIDC Bootstrap**

### Implementation Plan

#### Phase 1: Prepare Workflow (Automated)

Update `.github/workflows/npm-publish.yml`:

```yaml
# BEFORE
- name: Publish to npm with provenance
  working-directory: pkg
  run: npm publish --provenance --access public
  env:
    NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

# AFTER
- name: Ensure latest npm (>=11.5.1 for OIDC)
  run: npm install -g npm@latest

- name: Publish to npm with provenance
  working-directory: pkg
  run: npm publish --provenance --access public
  # NO TOKEN - OIDC handles auth via id-token: write permission
```

Add to `pkg/package.json` (generated by workflow):

```json
{
  "repository": {
    "type": "git",
    "url": "git+https://github.com/d-o-hub/chaotic_semantic_memory.git"
  },
  "publishConfig": {
    "access": "public",
    "provenance": true
  }
}
```

#### Phase 2: Manual First Publish (Human)

1. Build WASM locally:
   ```bash
   wasm-pack build --target web --scope d-o-hub --out-dir pkg
   ```

2. Ensure package.json has repository field

3. Publish manually:
   ```bash
   cd pkg
   npm publish --provenance --access public
   ```

#### Phase 3: Configure Trusted Publisher (Human)

1. Go to https://www.npmjs.com/package/@d-o-hub/chaotic_semantic_memory/access
2. Under "Trusted Publisher", click "GitHub Actions"
3. Configure:
   - **Organization/User**: `d-o-hub`
   - **Repository**: `chaotic_semantic_memory`
   - **Workflow filename**: `npm-publish.yml`
   - **Environment**: `npm` (optional)

4. Click "Set up connection"

#### Phase 4: Verify CI Publishing

1. Create new release tag
2. Monitor workflow for "Signed provenance statement" in logs
3. Verify package updated on npmjs.com

## Consequences

### Positive
- No secrets stored in GitHub
- Automatic provenance attestation
- Aligns with 2026 npm security standards
- Zero token rotation burden

### Negative
- Initial manual publish required
- npm UI configuration step needed
- Cannot be fully automated from day one

## Security

- OIDC tokens are job-scoped and short-lived
- Full provenance chain from commit to npm package
- No credential leakage risk
